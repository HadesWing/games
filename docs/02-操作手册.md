# 02 · 操作手册

从「本地能玩」到「真开播收礼物」，分四个阶段。**每个阶段都有验收标准，不达标不要往下走。**

| 阶段 | 目标 | 工作量 | 验收标准 |
|---|---|---|---|
| 0 | 本地跑通玩法 | 30 分钟 | 能自己玩完 5 局，分数看上去合理 |
| 1 | 接真实抖音弹幕 | 半天 | 榜单上出现陌生人发的词 |
| 2 | 叠进直播间画面 | 1 天 | 开播后观众能看到猜词画面 |
| 3 | 礼物联动变现 | 3–5 天 | 送礼能真的换到次数/提示 |
| 4 | 稳定性与合规 | 2 天 | 连播 6 小时不崩 |

# 阶段 0 · 本地跑通（今天就能做完）

## 0.1 启动

```bash
cd 弹幕猜词   # 换成你的实际目录
node server.mjs
```

看到这行就成功了：

```
  弹幕猜词 · 本地原型已启动
  打开: http://127.0.0.1:8830
```

浏览器打开 <http://127.0.0.1:8830>。

## 0.2 玩 5 局，重点看三件事

不要急着接弹幕。先回答三个问题，这三个问题决定后面要不要继续投入：

**① 分数看起来合理吗？**

随便输入几个词，问自己：

- 猜一个完全无关的词（比如答案是「纽扣」你猜「苹果」），应该在 15% 以下
- 猜一个同类的词（「扣子」「布扣」），应该在 80% 以上
- 猜答案里的某个字（「扣」），应该在 60–90%
- 猜一个特别泛的词（「衣」「东西」），应该明显低于具体词

如果「衣」的分比「襟」高，说明语义图谱建得不对，去改 `lib/lexicon.mjs`。

**② 节奏对不对？**

默认 90 秒一局。自己感受：

- 60 秒是不是太赶？（观众打字需要时间）
- 120 秒是不是太拖？（榜单 10 秒就填满了，后面没事干）

改：`ROUND_MS=120000 node server.mjs`

**③ 画面能不能看？**

远处看（手机屏幕上、缩到 30% 大小）。字号够大吗？颜色够清楚吗？

> 这一步很重要。直播画面在手机上是**巴掌大**，你在电脑全屏看着合适，观众看着就是一坨。

## 0.3 关掉模拟弹幕看「空场」

点右上角「模拟弹幕 · 开」关掉。

这时榜单只有你自己猜的词。**这是刚开播、没人看你的时候的真实画面。**

如果空场画面很尴尬（大片空白），说明需要加「等待文案」——去 `public/index.html` 里改 `.empty` 那段文字。

## 0.4 阶段 0 验收

- [ ] 服务能起，页面能开
- [ ] 自己猜 10 个词，分数排序符合直觉
- [ ] 猜中后 4 秒自动进下一局
- [ ] 倒计时结束能自动揭示答案
- [ ] 手机尺寸下文字看得清

# 阶段 1 · 接真实弹幕

> ⚠️ 这一步会碰到平台风控。**用小号测试，别拿主号试。**

## 1.1 先做一个决定：抓自己的直播间，还是抓别人的？

**抓自己的**——用于开播时给自己用。技术上更容易（自己房间的 URL 自己知道），但要注意别用主播账号登录浏览器，否则可能进主播视角。

**抓别人的**——用于研究竞品怎么写词库、什么词最难猜、一场能收多少礼物。这是**调研价值更高**的用法，建议先做这个。

**建议：先抓别人 3–5 场，攒数据，再决定自己播不播。**

## 1.2 拿到直播间短号

抖音直播间的网页版地址是：

```
https://live.douyin.com/745964462470
                            ↑ 这一串数字就是 web_rid（短号）
```

在 App 里分享直播间 → 复制链接 → 也能拿到。

⚠️ 注意区分两个 ID：

- `web_rid`（短号）：地址栏里那串
- `room_id`（长 ID）：每次开播会变，需要从页面 HTML 里正则抓

用现成开源库的话，它们会自己处理这个转换，你只要给短号。

## 1.3 路线 A：用 Python 库直连（推荐先试这个）

### 方式一：直接下编译好的 release（最省事）

1. 打开 <https://github.com/saermart/DouyinLiveWebFetcher>
2. 去 Releases 找最新编译版
3. 下载解压，按里面的说明填直播间地址
4. 双击运行

### 方式二：跑源码

```bash
git clone https://github.com/saermart/DouyinLiveWebFetcher.git
cd DouyinLiveWebFetcher
pip install -r requirements.txt
# 打开 main.py，把里面的直播间地址换成你的目标
python main.py
```

### 验收：看到这样的输出就算通

```
【聊天msg】[67197561586]说谎: 去拿
【礼物msg】X L 送出了 为你点亮x1
【统计msg】当前观看人数: 22164, 累计观看人数: 43.6万
```

**如果只看到进场消息、没有聊天消息**：房间可能真的没人说话，换一个大主播的房间试。

**如果报签名错误**：确认装了 Node.js（算签名要调 JS），然后重跑。

## 1.4 路线 B：用代理抓包（能抓直播伴侣）

如果路线 A 一直签名失败，或者你想抓**抖音直播伴侣**的弹幕（自己开播时的场景），用这个：

1. 下载 <https://github.com/xiaoli9/DouyinBarrageGrab> 的发行版（**不是源码包**）
2. **右键 → 以管理员身份运行**
3. 第一次启动会提示安装自签名证书 → 同意
4. 程序挂在后台不要关
5. **先开程序，再进直播间**（重要：只能抓握手之后的流量）
6. 本地会起一个 ws 服务：`ws://127.0.0.1:8888`

测试连通性：用任意 ws 测试网站连 `ws://127.0.0.1:8888`，能看到 JSON 推送就对了。

**关闭程序后如果上不了网**：网络设置 → 代理 → 关掉「使用代理服务器」。

## 1.5 把弹幕灌进猜词服务

已经写好桥接器 `ingest.mjs`，不用改服务端。

### 从代理（ws）接：

```bash
# 先干跑，确认字段对得上
node ingest.mjs ws ws://127.0.0.1:8888 --dry
```

正常的话会打印：

```
[dry] 张三 → 纽扣
[dry] 李四 → 衬衫
```

**如果是空的**：说明字段名不一样。打开 `ingest.mjs` 的 `extract()` 函数，把 `Content` / `Nickname` 这些键名改成你实际看到的。

### 从 Python 工具（stdout）接：

Windows 下管道比较麻烦，建议先重定向到文件再喂：

```bash
python main.py > danmu.log 2>&1
# 另一个窗口
tail -f danmu.log | node ingest.mjs stdin
```

或者干脆用 Python 那边直接 `POST` 到本地服务（见 1.6）。

确认无误后去掉 `--dry`：

```bash
node ingest.mjs ws ws://127.0.0.1:8888
```

同时把网页上的「模拟弹幕」关掉，避免真假混在一起。

## 1.6 或者：直接在 Python 里 POST（更稳）

在 `DouyinLiveWebFetcher` 的 `main.py` 里找到打印聊天消息的地方，加一行：

```python
import requests

def push_to_local(nickname, content):
    try:
        requests.post(
            "http://127.0.0.1:8830/api/guess",
            json={"user": nickname, "text": content},
            timeout=1,
        )
    except Exception:
        pass  # 本地服务没起就忽略，不影响抓取
```

然后在 `【聊天msg】` 那段打印后面调用 `push_to_local(昵称, 内容)`。

**为什么推荐这个**：少一层管道，少一个掉链子的环节。

## 1.7 阶段 1 排障表

| 现象 | 原因 | 处理 |
|---|---|---|
| 只打印进场，没聊天 | 房间没人说话 / 进错房间 | 换热门房间确认 |
| `signature` 相关报错 | Node 没装 / 版本太低 | 装 Node 18+ |
| `No match found` | 抓不到 roomId | 确认主播在播、地址格式对 |
| 跑一会儿程序崩了 | 服务端断开没重连 | 外面套个循环重启脚本 |
| 抓到弹幕但灌不进去 | 字段名不匹配 | 用 `--dry` 看实际结构 |
| 本地服务 404 | 端口不对 | 确认 `curl http://127.0.0.1:8830/api/state` |

# 阶段 2 · 叠进直播间画面

## 2.1 先想清楚：横屏还是竖屏

- **竖屏 1080×1920**：抖音主场景，手机观众体验最好
- **横屏 1920×1080**：适合游戏类、知识类直播

当前页面布局在两种尺寸下都能用，但**竖屏时左边题卡会显得偏窄**，建议竖屏开播前把 `public/index.html` 里 `grid-template-columns:330px 1fr` 改成 `380px 1fr`。

## 2.2 开 OBS 叠层模式

页面已经内置了叠层模式，加个参数就行：

```
http://127.0.0.1:8830/?overlay=1
```

效果：**背景透明**、隐藏底部输入框和右上角按钮，只剩题卡和榜单。

## 2.3 方案 A：抖音直播伴侣「窗口捕获」（不需要任何权限，推荐先做）

1. 打开 Chrome，访问 `http://127.0.0.1:8830/?overlay=1`
2. **F11 全屏**（这样捕获出来没有地址栏）
3. 打开抖音直播伴侣 → 开播
4. 添加素材 → **屏幕 / 窗口捕获** → 选那个 Chrome 窗口
5. 调整位置和大小

优点：零门槛，不需要第三方推流权限。
缺点：捕获的是整个窗口，弹幕画面会占满屏；想叠加摄像头要再添加一个「摄像头」素材放角落。

## 2.4 方案 B：OBS 推流（更灵活，但可能要权限）

**前提**：抖音对第三方推流有门槛，部分账号需要在直播伴侣里开通「第三方推流」权限。**先去确认自己的账号能不能推，别做完才发现推不上去。**

OBS 配置：

| 项 | 值 |
|---|---|
| 来源类型 | 浏览器 |
| URL | `http://127.0.0.1:8830/?overlay=1` |
| 宽 | 1080（竖屏）/ 1920（横屏） |
| 高 | 1920（竖屏）/ 1080（横屏） |
| FPS | 30 |
| 自定义 CSS | 留空（页面自己处理透明） |

关键设置：

- **关掉**「场景激活时刷新浏览器」——否则每次切场景都会重连，榜单会清空
- 「页面加载后关闭源」**不要勾**
- 建议再加一个「视频捕获设备」放角落做真人出镜

推流地址在抖音直播伴侣的「设置」里能拿到（RTMP 地址 + 推流密钥）。

# 阶段 3 · 变现功能

现在的版本**任何人可以无限猜**，没有次数限制。这是刻意留的缺口——你需要按自己的变现设计来加。

## 3.1 要加的四个东西

### ① 送礼 → 换猜测次数

数据模型：

```js
// 每个用户每局一个配额
const quota = new Map() // user -> { left: number }
```

逻辑：

- 开局每人给 3 次免费
- 收到 `WebcastGiftMessage` → 按礼物价值加次数
- `submitGuess` 里先扣次数，扣完了返回 `reason: 'no-quota'`
- 前端提示「次数用完了，送个礼继续」

改哪里：`server.mjs` 的 `submitGuess()` 开头。

### ② 送礼 → 解锁提示

现在 `state.hintOpen` 是靠点按钮加的。改成：收到指定礼物 → `hintOpen += 1`。

改哪里：`server.mjs` 里新增一个 `onGift(user, giftName, count)` 函数，由弹幕接入层调用。

### ③ 关注 → 换次数（限一次）

收到 `WebcastSocialMessage`（关注事件）→ 给一次大额次数，并标记已用。

### ④ 贡献榜

按礼物价值累加，每局/每场清零。这个纯展示，但**对攀比心理的刺激最强**。

## 3.2 礼物价值怎么算

抖音礼物消息里有 `gift.diamondCount`（钻石数）和 `repeatCount`（连击数）。价值 = 单价 × 数量。

**注意**：连击是增量推送的，不是一次性给完。要么按 `groupId` 聚合，要么每来一条加一次。

## 3.3 建议的定价结构（可直接抄）

| 礼物价位 | 给什么 |
|---|---|
| 免费（每天首次关注） | 5 次 + 1 条提示，仅一次 |
| 低价礼物（1 音浪级） | +10 次 |
| 中价（10 音浪级） | +50 次 |
| 高价（100 音浪级） | +500 次 + 直接解锁下一条提示 |
| 超高价（1000 音浪级） | 本局直接给答案位置提示 |

核心原则：**卖「次数」和「信息」，不卖「结果」**。详见 `01-调研与商业拆解.md` 第六节。

## 3.4 阶段 3 验收

- [ ] 次数用完提示正常
- [ ] 贡献榜按金额排序正确

# 阶段 4 · 上线前必须过一遍

## 4.1 技术

- [ ] **断线重连**：把网线拔了再插上，程序能自己恢复
- [ ] **长跑**：连开 6 小时，内存不涨、CPU 不飘
- [ ] **内存不爆**：`state.board` 每局要清空（已实现），`recent` 去重表要有上限（`ingest.mjs` 已加 3000 上限）
- [ ] **数据落盘**：每局结束后把 `{ round, answer, 所有猜测, 谁的礼 }` 追加到 JSONL。这是复盘唯一的依据
- [ ] **词库够用**：当前 `lib/lexicon.mjs` 只有约 155 个可出题的词。**截图里那个直播间已经刷到第 232 局了**——按每局一题算，你的词库撑不过一天。正式播之前至少要扩到 800–1000 词，且要按难度分层

## 4.2 内容

- [ ] 词库分级：简单（日常物品）/ 中等（专业词）/ 困难（生僻）
- [ ] 避免歧义词（一个词能对应多个近义答案）
- [ ] 每局的分类标签要和答案真的对得上

## 4.3 合规（最重要，别跳过）

- [ ] 不做「猜中给现金/实物」，奖励停留在榜单/称号/徽章
- [ ] 不设「付费必中」
- [ ] 自己去抖音规则中心 / 直播开放平台把互动玩法条款读一遍
- [ ] 未成年人打赏退款预案

⚠️ 我不是法律或平台规则专业人士。上面是风险提示，不是合规结论。要规模化做，找懂平台规则的人过一遍。

# 附：日常开播的操作顺序

每天开播前照着走，2 分钟搞定：

```
1. 起猜词服务         node server.mjs
2. 起抓弹幕（如用）    python main.py  /  DouyinBarrageGrab
3. 起桥接             node ingest.mjs ws ws://127.0.0.1:8888
4. 浏览器全屏打开      http://127.0.0.1:8830/?overlay=1
5. 直播伴侣开播 + 窗口捕获
6. 关掉网页里的「模拟弹幕」
```

下播后：

```
1. 停桥接 → 停抓弹幕 → 停服务
2. 看今天的 JSONL，找出「最难猜的词」和「最容易送礼的时刻」
3. 调词库和节奏
```
